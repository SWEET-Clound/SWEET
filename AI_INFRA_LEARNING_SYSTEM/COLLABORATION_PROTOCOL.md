# 你与 Codex 的长期学习—创造协作协议

## 1. 分工

你的责任：

- 决定每周真实可投入时间；
- 亲自运行实验并理解结果；
- 对代码、成本、安全和用户负责；
- 提供硬件、兴趣、时间和真实用户反馈；
- 对是否继续一个方向做最终决定。

Codex 的责任：

- 把阶段目标拆成可执行任务；
- 读代码、审查实现、补测试和文档；
- 帮助设计公平实验与反方解释；
- 跟踪 SGLang/vLLM 上游变化；
- 对 benchmark、PR 和技术结论做红队审查；
- 维护计划版本、记分卡和风险；
- 在证据不足时明确说“不足以得出结论”。

共同原则：

- 不把 AI 生成代码等同于你的能力；
- 不隐藏失败实验；
- 不为赶进度跳过正确性和复现；
- 不以课程完成率代替作品；
- 每季度允许修改路线，但必须留下理由。

## 2. 每周协作流程

### 周初

你提供：

- 本周可用小时；
- 上周周报；
- 当前阻塞；
- 是否有 GPU/预算变化。

Codex 输出：

- 本周唯一主问题；
- 3–6 个按顺序执行的任务；
- 每个任务的验收命令或证据；
- 风险和明确不做事项。

建议请求：

```text
根据 AI_INFRA_LEARNING_SYSTEM、最新周报和当前仓库状态，执行本周规划。
本周可投入 __ 小时。先审计上周证据，再给出唯一主目标；能直接修改和验证的内容请完成，不要只给建议。
```

### 实现中

遇到问题时提交：

- 期望行为；
- 实际行为；
- 最小复现命令；
- 完整错误；
- 已尝试内容；
- 相关实验编号。

Codex 先诊断再修改；如果只是解释请求，不擅自实施额外变化。

### 周末

你提供运行结果和用户反馈，Codex：

- 填写或审查周报；
- 对照 Definition of Done；
- 更新证据等级；
- 判断继续、延长或回退；
- 只确定下周一个主目标。

建议请求：

```text
审计本周结果是否通过验收。不要因为代码能运行就判定通过；检查测试、原始数据、复现和解释。
更新周报、记分卡、roadmap 状态，并给出下周唯一主目标。
```

## 3. 实验协作

每个性能实验开始前，Codex 必须帮助检查：

- 假设是否可证伪；
- 比较是否公平；
- 环境/commit/model/precision 是否固定；
- warmup 和重复次数；
- 负载分布；
- 正确性/质量门槛；
- 统计波动；
- 原始数据保存位置；
- 哪些结论不能推出。

实验完成后至少做一次反方审查：尝试用缓存、冷启动、请求长度、随机性、错误样本遗漏或测量工具开销解释所谓提升。

## 4. 上游贡献协作

在开 Issue 前：

- 搜索重复 Issue/PR；
- 用最新 main 复现；
- 缩小最小复现；
- 提供环境和 commit；
- 区分使用问题、bug 和 feature request。

在开 PR 前：

- 阅读贡献指南和目标目录约定；
- 确认修改范围最小；
- 写回归测试；
- 跑相关检查；
- 对性能改动给出正确性和多次测量；
- 由 Codex 做一次维护者视角 review；
- 最终内容必须由你理解并认可。

## 5. 月度协作

每月最后一周，Codex 应：

1. 汇总 `SCORECARD.csv`；
2. 检查作品是否可复现；
3. 找出投入最多但证据最弱的活动；
4. 删除或延后低价值任务；
5. 扫描上游重大变化；
6. 确定下月唯一能力主题；
7. 更新风险登记。

## 6. 季度协作

每季度重新进行三项独立审计：

- 技术生态审计：项目、路线图、采用和替代者；
- 职业红队审计：哪些能力正在商品化；
- 个人证据审计：Gate 是否真正通过。

只有个人证据审计通过，才允许提高路线置信度。生态很热门但个人没有成果，不算通过。

## 7. 必须由人完成的口试

每个阶段结束时，Codex 随机提出至少 10 个问题，覆盖：

- 数据流；
- 关键不变量；
- 失败模式；
- 指标含义；
- 实验限制；
- 源码调用链；
- 一个替代设计。

你需要不依赖 AI 生成答案进行解释。答不出的主题退回 E1/E2，不因代码存在而判为掌握。

## 8. 权限与成本规则

- 默认只修改当前学习仓库；
- 任何付费云资源、公开发布、上游 Issue/PR 均在执行前明确确认；
- 不自动购买硬件或服务；
- 不把私有日志、密钥、用户语音或敏感数据提交到仓库；
- 数据脱敏方案必须先于真实会话长期保存。

## 9. 第一次协作启动

下一次对话直接提供：

```text
开始执行 AI_INFRA_LEARNING_SYSTEM 第 1 周。
我每周稳定可投入 __ 小时；电脑 CPU/内存/GPU 为 __；每月可接受预算为 __；
我更偏好 __（系统/产品/研究），最担心的是 __。
请先检查环境和现有代码，然后和我一起完成本周交付，不要只生成教程。
```

如果这些信息暂时不全，按每周 15 小时、H0 无可用 NVIDIA GPU、零付费预算的保守假设启动，并在得到新信息后更新路线。
