# 学习包执行标准（v2）

本文件是 Week 3–12 的**质量合同**。它解决一个常见误区：主题清单不是学习路径；链接集合也不是练习。只有“可从零执行、会失败也知道如何返回、能留下证据”的任务才计入学习。

## 时间模型与诚实边界

- 每周 **10 小时核心**：完成进入 Gate、五次 Session、最小 SGLang Lab、练习和证据；SGLang Lab 的约 2 小时通过四个 20–40 分钟微循环嵌入五次 Session，**不是额外加时**。
- 每周 **5 小时深化**：只在核心全部通过后做；未完成核心时，不用深化任务掩盖缺口。
- 若一周实际只有 6 小时：只做 Session 1–3 和 SGLang Lab 的 `最小` 路径；记录“未完成”，下周先回补。不得跳关。
- 12 周约 180 小时的可验证承诺是：获得**安全阅读和贡献 SGLang 的入口能力**、完成一个可回放 workload 资产、能验证本地 cache/调度假设。它不能等同于“完全掌握持续演进的 SGLang”。项目级掌握还需要 12 周后的 benchmark、外部 review、PR 与第三方复现。

## 每个学习板块的固定循环（90–120 分钟）

1. **Gate（5 分钟）**：运行上次的最小测试；失败则先修复，不开始新内容。
2. **预测（5 分钟）**：在 Work Log 写“我预计命令/代码会发生什么，为什么”。
3. **定向阅读（20–35 分钟）**：只读本周 Resources 指定材料，回答 3 个问题；不要跳到无关的内核、集群或教程。
4. **最小实现（30–45 分钟）**：先让一条失败测试变绿，再扩大案例。一次只改一个行为。
5. **验证（10–20 分钟）**：运行给定命令，保存摘要输出/原始数据；不得只截图。
6. **解释与停止（10 分钟）**：写观察、反例与下一步。达到 Stop line 后停；没有通过就走失败分支。

每个板块的练习必须包含：A 预测题、B 引导 red→green 题、C 独立反例/迁移题；高风险板块再增加故障注入。完整映射见 [板块—练习清单](MODULE_EXERCISE_MANIFEST.md)。

## 每周必须拥有的可检查证据

| 证据 | 最低要求 | 不算证据的例子 |
| --- | --- | --- |
| 环境 | Python、依赖、OS/GPU 与命令输出 | “我已经安装了” |
| 正确性 | 测试名、命令、输出、反例 | 代码没有报错 |
| 实验 | 假设、raw CSV/JSONL、配置、解释 | 一张图或单次耗时 |
| 源码 | 固定 commit SHA、文件/符号、调用图、一次实际 test/观察 | main 分支书签 |
| 复盘 | 未解决风险、边界、下一周 Gate | “学会了” |

## 练习题必须包含的字段

每道可执行练习都要写明：`起始位置`、`输入`、`预期结果/断言`、`运行命令`、`反例`、`提示`、`完成证据`。如果当前仓库结构与计划不同，先在 Work Log 记录差异，再选择等价的目标文件；不要凭空修改不理解的生产逻辑。

## SGLang Lab 的版本规则

每周 Lab 均遵守：

1. clone 到 `external/sglang`（若尚未 clone）；首次记录 `git rev-parse HEAD` 到 `sglang_notes/pinned_revision.md`。后续阅读、测试和笔记引用该 SHA，不能写笼统的 `main`。
2. SGLang 使用**独立环境**。不要把它的依赖装进当前 Agent 或 `mini_inference_lab` 环境。
3. 首选 CPU unit test 或静态调用图；没有硬件时禁止伪造 GPU 性能结论。
4. 每周至少产生：阅读卡、一个可复现命令、一个调试观察/测试结果，以及一个与本周本地练习的“可类比/不可类比”表。
5. 不直接改上游源码作为练习。要改动时先建最小复现、写测试、保存 diff；任何 PR 仍需单独审查。

## 价值资产副线（每周累积而不是一次性造大项目）

资产根目录建议为 `workloads/agent_cache_lab/`。所有样本必须脱敏，不能保存 API Key、完整私人提示词、身份信息或真实模型输出。

| 周 | 新增资产 | 最低验收 |
| ---: | --- | --- |
| 3 | schema 草图与数据分类表 | 能说明哪些字段绝不收集 |
| 4 | request trace JSONL v0 | 有 request_id、时间、输入长度、结果类别 |
| 5 | cancel/finish 事件 | 一请求恰好一个 terminal event |
| 6 | shared-prefix/multi-turn workload generator | seed 固定可生成相同 JSONL |
| 7 | failure label taxonomy | 每类能指向 trace 或测试 |
| 8 | 数据卡 v0.1 | 来源、脱敏、限制、删除策略 |
| 9 | token/shape/cost 注释 | 能估计 tensor/cache 字节数 |
| 10 | attention cost annotation | 能区分理论与实测 |
| 11 | decoder replay harness | 同 seed/config 可重放 |
| 12 | cache benchmark report | raw data、correctness、局限完整 |

## 通过、暂停与回补

- **通过**：核心 Rubric ≥80，所有硬门槛通过，且能口头解释一个反例。
- **暂停**：外部依赖、硬件或版本使核心命令无法运行时，保存完整报错和环境；改做 CPU/假实现路径，不捏造结果。
- **回补**：下周 Session 1 必须先完成上一周红色项目。连续两周未通过时，压缩新主题并在周末执行一次 60 分钟诊断，而不是同时补两周的新内容。
