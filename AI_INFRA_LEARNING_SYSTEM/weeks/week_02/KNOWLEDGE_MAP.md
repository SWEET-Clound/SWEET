# Week 2 知识地图

这不是第二套课程；它是本周遇到术语时的短词典。

## Demo 和小工程的差别

| 维度 | Demo 常见状态 | Week 2 最低状态 |
| --- | --- | --- |
| 配置 | 任意位置读变量，缺失后奇怪失败 | 集中检查，错误可行动 |
| 计算 | `eval` 快速演示 | 仅执行明确允许的数学规则 |
| 导入 | import 时初始化外部对象 | 可测试定义和真实启动分开 |
| 错误 | 直接展示异常 | 分类、稳定、不泄露秘密 |
| 测试 | 手工运行一次 | 核心规则可离线反复验证 |
| 依赖 | “我环境刚好有” | 安装步骤和版本有记录 |

## 模块、package、导入、入口点

```text
Agents/                 ← package：组织相关模块
  __init__.py           ← 显式 package 标记
  config.py             ← 配置规则
  safe_calculator.py    ← 有限算术规则
  errors.py             ← 错误类别和公开文案
  study_assistant.py    ← 主程序：连接 LangGraph
```

- **模块**：一个可被导入的 `.py` 文件；
- **package**：用统一前缀组织的一组模块；
- **import**：先执行模块顶层语句，再提供定义；
- **入口点**：用户明确启动程序才经过的路径；Key 检查、模型创建、网络调用应靠近这里；
- **factory**：例如 `create_graph()`，将“如何创建”与“现在就创建”分开。

判断口诀：一个文件被测试导入时，若会触网、读取秘密、创建昂贵对象或修改外部状态，它的顶层设计需要被审视。

## 纯逻辑与外部边界

| 类型 | 相同输入是否应同结果 | 例子 | 测试办法 |
| --- | --- | --- | --- |
| 纯逻辑 | 是 | 路由关键字、AST 算术、错误文案 | 普通 pytest |
| 配置边界 | 取决于环境 | `os.getenv` | `monkeypatch.setenv/delenv` |
| 模型/网络 | 不保证 | `model.invoke` | 假对象/集成测试 |
| 文件/数据库 | 不保证 | 保存记忆、写日志 | 临时目录/测试替身 |

`monkeypatch` 不是伪造现实：它让测试暂时控制外部变量。例如删除 Key 来测试“缺 Key 时会怎样”，测试结束后 pytest 恢复环境。

## 契约与错误

函数契约就是：**给定什么输入，承诺什么输出或哪种错误。**

```text
安全算术输入：长度有限的字符串，只含数字、括号、一元 +/-、+ - * /
输出：数值字符串
其他情形：明确的“不支持表达式”或“不能除零”错误
```

| 错误类别 | 先行动者 | 例子 |
| --- | --- | --- |
| 输入错误 | 用户 | 空算式、`name + 1` |
| 配置错误 | 操作者 | Key 缺失/空白 |
| 依赖故障 | 服务或操作者 | 超时、DNS、provider 故障 |
| 内部错误 | 开发者 | 程序承诺支持却没有处理的 bug |

公开消息告诉用户下一步，但不包含 Key、完整环境变量、原始 traceback、服务器路径或供应商原文。

## 为什么不用 `eval`

`eval` 的能力远大于“算四则运算”。正确路线是默认拒绝：

```text
表达式字符串 → ast.parse → 检查每个节点是否在白名单 → 只计算获准节点
```

只允许数字、加减乘除和括号；函数调用、名字、属性访问、`**` 等没有明确说明的能力默认拒绝。

## 测试层次

| 层次 | 问题 | Week 2 例子 | 真实模型？ |
| --- | --- | --- | --- |
| 单元 | 小规则对吗？ | `calculate("2+3")`、路由 | 不要 |
| 组件 | 小模块组合对吗？ | tool 转换计算器错误 | 不要 |
| 集成 | 图、模型、依赖能一起跑吗？ | 完整 LangGraph | 以后 |
| E2E | 用户体验正确吗？ | 真实会话 | 以后 |

离线测试不是躲难题，是控制变量：路由失败时，你能确定原因来自路由规则，而不是网络、Key、账单或模型波动。

## 本周应能说出的五句话

1. import 会运行顶层语句，所以顶层副作用会阻碍无关逻辑的测试。
2. 配置缺失是预期运行条件，应在真实启动边界明确检查。
3. AST 白名单比 `eval` 更符合“只允许有限算术”的需求。
4. 输入、配置、依赖、内部错误有不同责任人。
5. 离线单元测试证明列出的规则，不等于模型、网络和整个产品都正确。
