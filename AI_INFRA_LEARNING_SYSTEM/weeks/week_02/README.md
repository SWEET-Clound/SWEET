# Week 2：配置、安全与复现

> 目标：把 `Agents/study_assistant.py` 从“可运行 Demo”推进到“可安全修改、可离线验证的小工程”。

## W2-1：代码地图与导入副作用（1.5 小时）

**作用：** 理解“模块、导入、函数定义、函数调用”四者不同，解释当前为何难以测试路由。

| 概念 | 白话解释 | 当前例子 |
| --- | --- | --- |
| 模块 | 一个可被其他文件导入的 `.py` 文件 | `study_assistant.py` |
| 顶层语句 | import 时立即执行的语句 | `model = init_chat_model(...)` |
| 导入副作用 | 导入不仅拿到定义，还创建/读取/修改外部东西 | 初始化模型、绑定工具、编译 graph |
| 入口点 | 用户显式启动程序才应经过的路径 | 将来的 `main()` 或 factory |

**资料（最多 25 分钟）：** [Python Modules](https://docs.python.org/3/tutorial/modules.html) 只读“模块和 import”；[Python `__main__`](https://docs.python.org/3/library/__main__.html) 只读入口点；随后看自己的导入区、模型初始化、工具、`router_node`、图构建区。

**路径：**

1. 不改代码，在 `WORK_LOG.md` 填至少 8 行：代码位置、作用、导入时是否执行、是否有外部依赖；
2. 标注 `router_node` 为纯逻辑，`os.getenv` 为配置边界，`init_chat_model` 为依赖边界，`builder.compile` 为构建动作；
3. 预测没有 LangGraph 或 Key 时第一个失败点；
4. 写出未来职责表：`config.py` 管配置，`safe_calculator.py` 管算术，`errors.py` 管公开文案；
5. 完成 E1。

**通过：** 能解释为什么 `def router_node` 被导入时不运行函数体，而 `model = init_chat_model(...)` 会运行右侧表达式。

## W2-2：配置契约（1.5 小时）

**作用：** 将 Key 视为外部配置而非业务逻辑。缺少时应在真实启动前明确报错，不泄露值。

| 情形 | 正确行为 | 不应做 |
| --- | --- | --- |
| 不存在 | 抛明确配置错误 | 静默传 `None` 给模型 |
| 空白 | 与不存在相同 | 当作可用 |
| 有值 | 返回给调用者 | 打印值 |
| provider 拒绝 | 标为依赖故障 | 说成用户输错 |

**路径：**

1. 先填 E2 行为表；
2. 新建空的 `Agents/__init__.py`，让目录成为显式 package；
3. 新建 `Agents/config.py`，实现 `get_required_env(name: str) -> str` 和 `ConfigurationError`；
4. 变量不存在或 `strip()` 后为空时抛异常，否则返回值；不打印值；
5. 在 `tests/test_config.py` 写 3 个独立测试：不存在、空白、有效。用 pytest `monkeypatch` 临时改变环境；
6. 先运行单文件，再运行全部离线测试；
7. 最后才让主程序的真实启动路径调用它。**仅导入纯函数时不应要求 Key。**

**通过：** 三类行为均有测试；错误文本没有密钥；能解释配置缺失不是模型回答错误。

## W2-3：安全计算器（2 小时）

**作用：** `eval` 能执行 Python 表达式，能力远大于“算四则运算”。需求应是默认拒绝、只允许明确规则。

| 概念 | 最小解释 |
| --- | --- |
| AST | Python 将表达式解析出的语法树 |
| 白名单 | 默认拒绝，只放行明确的能力 |
| 输入契约 | 明确支持什么、拒绝什么及报什么错 |
| 资源边界 | 合法语法也限制异常长/大的工作 |

**资料（最多 20 分钟）：** [Python `ast`](https://docs.python.org/3/library/ast.html) 中 `parse` 的最小示例。只认识 `Expression`、`BinOp`、`UnaryOp`、`Constant`。

**路径：**

1. 先填 E3 行为表；
2. 新建 `Agents/safe_calculator.py`，用 `ast.parse(expression, mode="eval")`；
3. 递归只接受数字、括号、二元 `+ - * /`、一元 `+/-`；其他节点抛自己的输入错误；
4. 拒绝空白与超过 200 字符的输入；拒绝 `Pow`（`**`）；将除零转为稳定错误；
5. 在 `tests/test_safe_calculator.py` 先写一个应失败的非法输入测试（Red），最小实现让它通过（Green），再整理重复逻辑（Refactor）；
6. 将原 `@tool calculator` 改为调用安全函数并把内部异常转为稳定提示；
7. `rg -n "eval\\(" Agents` 确认无命中。

**必测：** 正确的 `2 + 3 * 4`、`(10 - 4) / 2`、`-5 + 8`；拒绝空白、`name + 1`、`__import__('os')`、`2 ** 100`；稳定处理 `1 / 0`。

**通过：** 8+ 行为测试，没有 `eval(`，你能说清“允许什么”，而非只说禁止一个危险字符串。

## W2-4：错误分类与测试接缝（2 小时）

**作用：** “报错”不足以行动。区分责任人，才知道要改输入、补配置、等待依赖，还是修 bug。

| 类别 | 例子 | 先行动者 |
| --- | --- | --- |
| 输入错误 | 空算式、未知语法 | 用户 |
| 配置错误 | 缺少 Key | 操作者 |
| 依赖故障 | 超时、网络不可用 | 服务/操作者 |
| 内部错误 | 未预期代码 bug | 开发者 |

**路径：**

1. 完成 E4 的 8 个分类；
2. 新建 `Agents/errors.py`，定义少量异常或纯函数 `public_error_message(kind)`；不把异常原文直接给用户；
3. 写 `tests/test_error_messages.py`，四类各一个案例，断言不泄露 Key、绝对路径、traceback；
4. 让计算器输入错误走稳定文案；
5. 建立 `Agents/routing.py`，只保留 `classify_task_type(user_input: str) -> str` 这个纯函数；再建立 `tests/test_router.py`，只导入新模块。之后才让 `router_node` 调用它；不能用真实 Key 绕过原文件导入会建模型的问题；
6. 覆盖计算、计划、本地知识、空白、普通聊天五类输入；
7. 不配置 Key、不联网运行这些测试；在日志写出 `bind_tools 有什么作用？` 的静态路径。

**通过：** 4+ 错误测试、5+ 路由测试均离线通过。能解释 mock 的目的在于替换无关外部边界，而不是“让测试永远通过”。

## W2-5：依赖清单与复现（1.5 小时）

**作用：** “我电脑能跑”不等于可复现。别人需要知道 Python、直接依赖、秘密边界、离线测试命令和真实调用边界。

| 文件 | 应放什么 | 不应放什么 |
| --- | --- | --- |
| `requirements.txt` | 已验证的直接运行依赖及版本 | Key、无关机器包 |
| `requirements-dev.txt` | 开发/测试依赖 | 生产秘密 |
| `.env.example` | 变量名和占位符 | 真实值 |
| `.gitignore` | 本地私有文件规则 | 唯一的安全保障 |

**路径：**

1. 阅读当前 `requirements-dev.txt` 与 `.gitignore`，写下各自已解决/未解决的问题；
2. 列出主程序的直接第三方导入；不要猜版本；
3. 只在实际安装并验证后，将可用版本记入 `requirements.txt`；
4. 新建 `.env.example`，例如 `DEEPSEEK_API_KEY=replace_with_your_key`；
5. 在 `Agents/README.md` 或根 README 写创建 venv、安装开发依赖、跑离线测试、设置本地 Key、真实调用何时发生；
6. 不删除现有 `.venv`，另建你明确命名的临时环境来验证离线测试；记录结果后才可删除该临时目录。

**通过：** 新终端不靠猜路径即可跑离线测试，Git 文件从未包含真实秘密。
