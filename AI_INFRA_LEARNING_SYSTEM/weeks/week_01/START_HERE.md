# Week 1 从这里开始

这份文件是 Week 1 的入口。暂时不要试图一次读懂目录中的所有文件。

## 1. 这周到底在学什么

Week 1 只解决四个问题：

1. **环境可信吗？** 同一份代码是否总由明确的 Python 和依赖运行？
2. **代码可信吗？** 不调用真实大模型，能否证明路由等基础逻辑正确？
3. **过程看得见吗？** 给定一句输入，能否说出它依次经过哪些节点？
4. **失败能描述吗？** 出错时，能否说清触发条件、影响和验证方法？

它们的关系是：

```text
可信环境
  ↓
可信测试
  ↓
看懂一次执行过程
  ↓
知道过程可能在哪里失败
```

后续 SGLang、GPU 性能和分布式系统都会反复使用这四种能力。

### TRACE.md 到底是什么

假设用户输入：

```text
bind_tools 有什么作用？
```

Agent 不会瞬间得到答案。它实际经历：

```text
创建初始状态
→ router_node 判断问题类型
→ route_by_task_type 选择下一站
→ knowledge_node 查询本地知识
→ 生成 AIMessage
→ 结束
```

`TRACE.md` 就是把这次“旅行”记录下来。它不是新框架，也不是要背的格式。它帮助你回答：

- 为什么走到了这个节点？
- 每一步读了什么数据、改了什么数据？
- 如果答案错误，最先检查哪里？
- 哪个测试能防止同类错误再次发生？

测试回答“某个行为是否符合预期”；trace 回答“整个过程是怎样发生的”。两者用途不同。

## 5. 接下来只做三步

### 第一步：理解刚刚通过的 pytest 测试

目标：理解“测试通过”和“需求被充分证明”是两件事。阅读 `LESSON_01_PYTEST.md` 并填写行为表。

完成标志：能解释为什么当前输出是 `1 passed`，并说出它证明了什么、没有证明什么。

### 第二步：巩固一个最简单的测试

使用 `practice/test_grade_detect.py`，学习：

- 被测函数是什么；
- 输入和期望输出是什么；
- 为什么边界值 0、60、90、100 特别重要；
- 为什么多个 assert 最好拆成参数化用例；
- 当前函数对 101、负数、非整数的行为是否清晰。

完成标志：你能不看资料解释这个测试“证明了什么”和“没有证明什么”。

### 第三步：测试 Agent 的纯路由

暂时不测试 LLM，不测试 API，不测试 streaming。只测试：

```text
输入一句话 → router_node 返回哪个 task_type
```

完成标志：至少 5 类输入在无 API Key、无网络时通过。

完成这三步以后，再进入 `TRACE.md`。失败目录放在 trace 之后，不需要现在硬填。
