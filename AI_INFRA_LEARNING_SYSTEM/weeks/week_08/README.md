# Week 8：Gate 0A——工程地基审计与方向选择

> 10 小时核心 + 5 小时深化。主问题：**我是否具备进入 PyTorch / 推理系统学习的工程地基，并且真的愿意继续做测量与调试？**

先读 [START_HERE.md](START_HERE.md)。本周不增加新功能；资料与审计边界在 [RESOURCES.md](RESOURCES.md)，执行问题在 [EXERCISES.md](EXERCISES.md)，证据统一填入 [WORK_LOG.md](WORK_LOG.md)，按 [RUBRIC.md](RUBRIC.md) 决定进入 Week 9 或延长。

这不是“再加功能”的一周。它把 Week 1–7 的证据组合成可复查结论。任何没通过的工程硬门槛优先修复，不用新技术掩盖。

## 本周必须交付的产出

1. `experiments/week_08/evidence_index.md`：逐项链接环境、测试、负载、trace 和故障证据；
2. `experiments/week_08/stability_run.md`：30 分钟运行的原始日志、指标与中止条件；
3. 干净虚拟环境复现记录：包含偏离文档的命令（若有）；
4. `reviews/YYYY-W08.md`：不少于 2,000 字的工程复盘；
5. `gate_0a_decision.md`：继续、延长工程阶段或转向的明确选择及证据。

缺其中任何一项，Week 8 不通过；“我已经看过前面内容”不是产出。

## 五个学习板块

### W8-1：可审计清单（2 小时）

建立 `experiments/week_08/evidence_index.md`，逐项链接而非口头声称：环境重建、测试数、质量门、API contract、取消证据、负载 raw data、trace、故障注入、ADR、失败目录。

**练习：** 对每项标证据强度：直接命令输出 / 原始数据 / 二手描述 / 缺失。二手描述不能作为 Gate 通过依据。

### W8-2：30 分钟稳定运行（3 小时）

**路径：**

1. 固定版本与 fake provider workload；
2. 运行 30 分钟小负载，记录请求数、成功率、P95、queue depth、task count、内存（能采则采）；
3. 预先定义中止条件：错误率、未回收 task、队列持续满；
4. 发生异常时保留原始日志/trace，不立刻重启覆盖证据；
5. 写运行报告和未解释异常表。

**验收：** 不等于零错误；要求每个错误可分类、可定位、可说明是否恢复。

### W8-3：干净环境复现演练（3 小时）

**路径：**

1. 在新建、不覆盖的 venv 从 README 开始；
2. 只安装文档声明的依赖；
3. 跑质量门、离线测试、fake service health；
4. 记录每条偏离文档的命令；
5. 修文档后再从头验证一次。

**练习：** 列三类“机器上侥幸有但文档没写”的隐性依赖，并给出如何暴露它们。

### W8-4：2,000 字工程复盘（4 小时）

必须回答：

1. 最初 demo 的三个风险及如何验证；
2. 哪个测试捕获过真实回归或设计误解；
3. 负载实验饱和点由什么证据支持；
4. 一个 trace 如何缩短定位；
5. 哪些结论仍只在 fake provider 下成立；
6. 我对并发 bug、失败分析、实验记录的主观感受与客观投入；
7. Week 9–12 为什么从 Tensor/Attention/KV Cache 开始，而不是直接安装大 serving 框架。

### W8-5：Gate 决策（3 小时）

| Gate 项 | 通过证据 |
| --- | --- |
| 可维护工程 | 质量门、60+ 测试、模块边界 |
| 可复现实验 | 5 次并发矩阵、raw data、说明 |
| 故障定位 | 五类 trace 与修复 |
| 持续兴趣 | 复盘中明确、有证据的判断 |

若前三项任一失败：延长当前阶段并修补，不进入模型实验。若全部通过但持续厌恶测量/调试：转向 Agent 评测/产品工程仍是成功决策，而非失败。若通过：进入 Week 9。

**本周 DoD：** evidence index、30 分钟报告、干净复现、2,000 字复盘、明确 continue/pivot 决策。不得以“安装了 PyTorch”替代 Gate。
