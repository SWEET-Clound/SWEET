# 多智能体方案评审与第二轮升级记录

评审日期：2026-09-06  
评审对象：`quant_demo/` 当前实现  
参与视角：代码规范与可靠性、原方案符合度、量化研究与市场微观结构

## 1. 总结结论

当前方案是一个边界清晰、能够教学和离线验证的最小 Demo，但不能称为成熟量化系统，也没有证据证明策略具有稳定收益。

| 维度 | 评审结论 | 当前证据 |
| --- | --- | --- |
| 学习路径 | 完善 | 有八周路线、实验模板、复盘流程和风险边界 |
| 架构方向 | 合理 | 单脚本、两项直接依赖、无券商权限，故障面较小 |
| 成交时序 | 基本可靠 | 内置自检证明 T 日信号只在下一根日线开盘处理 |
| 数据可信度 | 教学级 | 有校验、快照和分红保护，但免费上游无 SLA，缺正式交易日历核对 |
| 回测研究纪律 | 改进后可用 | 有同成本基准、holdout、压力测试和训练段参数邻域 |
| 纸面交易 | 观察工具 | 有幂等账本和漏跑保护，但没有券商撮合、订单回报或对账 |
| 量化成果 | 尚未产生 | 当前没有真实行情缓存、回测输出或 120 日纸面记录 |
| 实盘准备度 | 不具备 | 未接券商、未验证合规、无账户级风控和 kill switch |

因此，现阶段最准确的定位是“优秀方向上的教学原型”，而不是“优秀交易策略”或“可实盘系统”。

## 2. 第一轮独立审查发现

### 代码规范与可靠性视角

- 510300 已知有历史分红，分红接口空表不能被解释为零分红；
- holdout 从首个收盘净值开始会漏掉边界首日收益和费用；
- 数据校验需要拒绝 `NaN` 之外的正负无穷值；
- 公共函数需要统一字符串日期和数字输入；
- 单文件职责较多，但这是当前明确约束，尚不足以支持拆包。

### 原方案符合度视角

- 回测、纸面、缓存、三类结果文件和内置自检均已存在；
- 压力场景原先只报告 holdout，缺少完整区间；
- 无交易时的 `trades.csv` 原先可能没有表头；
- CSV 与元数据分别替换，不能严格保证旧缓存始终可恢复；
- 没有新增独立 test 文件，符合仓库要求。

### 量化研究视角

- 次日开盘成交、原价记账、前复权信号、现金分红和同成本基准值得保留；
- 硬编码 2023 年起点不能被宣传为真正独立 OOS，只能叫 holdout；
- 原纸面模式在漏跑后按已过去的历史开盘补成交，不够诚实；
- 固定费用压力测试不足以证明策略稳健，需要先看相邻参数平台；
- 没有真实回测结果时，不能声称有 alpha、统计显著性或可实现滑点。

## 3. 交叉讨论与取舍

### 一致通过

1. 对 510300，分红空响应必须失败且不能覆盖当前缓存；
2. holdout 收益以前一交易日净值为基线，活动统计从 holdout 首日开始；
3. 压力场景同时报告完整区间与 holdout；
4. 非有限数值、字符串日期和空交易表结构必须有内置验证；
5. 相邻参数检查只能使用 2023 年前训练段，不查看 holdout、不选择赢家。

### 有分歧后采用的决定

- **缓存原子性**：没有采用自定义“注释头 CSV”。改为不可变普通 CSV 快照加原子 `current.json` 指针；既能用常规工具读取，又能在指针替换失败时继续使用旧快照。
- **漏跑成交**：规格审查倾向继续兑现缺口前的待成交目标，量化审查认为程序并未真的向市场提交订单。最终选择更保守的 `MISSED_WINDOW`：超过一根新日线时不事后补成交，只保留持仓、计入分红并生成最新待处理目标。
- **模块拆分**：审查发现单文件存在职责集中，但没有第二种数据源、策略或券商实现。本轮不为潜在需求增加接口与包结构。

## 4. 本轮已实施升级

- 510300 分红空表现在会明确失败；
- 数据校验拒绝 `NaN`、`Inf`、负价格和非法 OHLC，并允许成交量为零的不可交易日线被阻断；
- 回测和纸面入口统一规范化日期与数字类型；
- holdout 边界以前一收盘净值计收益，同时不污染首日后的交易、费用和暴露统计；
- 压力场景新增完整区间结果；
- 空交易输出保留稳定列结构；
- 缓存改为内容寻址的不可变 CSV 快照与原子 current 指针；
- 纸面漏跑多日记录 `MISSED_WINDOW`，不伪造历史成交；
- 新增 `robustness` 命令，在训练段报告固定 3×3 均线邻域及 min/median/max；
- `self-check` 扩展覆盖分红参考价、字符串输入、无穷值、空交易表、漏跑和稳健性隔离。
- 分红日期与行情不对齐时抓取失败，纸面账本最后日期从行情消失时拒绝推进；
- 稳健性九组参数使用统一的 70 日热身基线，并在切断 holdout 后才做数值校验；
- 回测与稳健性输出目录加入配置和输入行情快照指纹，摘要记录完整配置与快照 SHA-256；
- 自动结果只称 `holdout_gates_passed`，不代替人工纸面晋级判断。
- v1 封闭为只接受 510300，并补齐一字跌停卖出分支的离线断言与七步人工验收清单。
- 普通回测和纸面 CLI 封闭为固定 20/60；相邻参数只允许通过不选优的 `robustness` 查看。
- holdout 门槛新增样本资格，零回撤 Calmar 改为 `null`，压力滑点保证不低于基础配置。

## 5. 仍未解决且不能被包装成成果的事项

- 没有实际运行 AKShare 在线接口，字段、连接稳定性和分红完整性尚未在本机验证；
- 没有真实 `summary.json`，因此没有 CAGR、回撤、费用、交易次数或 holdout 结论；
- 10 个自然日陈旧阈值只是灾难保护，不能替代“最近已完成交易日”的正式日历判断；
- 免费分红接口没有现金支付日，当前在除息日把分红视为可用现金，可能提前购买力；
- 一字涨跌停判断来自日线启发式，不能代表真实盘口排队；
- 前复权历史可能在后续分红后重算，不同缓存快照的信号可能漂移；
- 参数邻域只能显示局部稳定性，不能证明统计显著性或跨标的泛化；
- 纸面成交是预先留痕后的理论开盘成交，不是模拟券商订单回报；
- 尚未经历 120 个交易日、一次完整状态切换和逐日账本核对；
- 不具备实盘所需的券商适配、权限隔离、对账、风控停机与程序化交易报告流程。

## 6. 下一轮以证据驱动的升级顺序

### A. 先产出真实量化结果

用户安装 Python 后依次运行：

```powershell
.\.venv\Scripts\python.exe .\quant_demo\quant_demo.py self-check
.\.venv\Scripts\python.exe .\quant_demo\quant_demo.py fetch --symbol 510300 --start 2013-01-01
.\.venv\Scripts\python.exe .\quant_demo\quant_demo.py robustness --symbol 510300
.\.venv\Scripts\python.exe .\quant_demo\quant_demo.py backtest --symbol 510300
```

审查 `runtime/cache/510300/current.json`、`robustness_510300_<config-tag>_<data-tag>/` 和 `backtest_510300_20_60_<config-tag>_<data-tag>/`。只有这些文件真实存在并通过人工抽查后，才能讨论策略的数值结果。

### B. 再验证执行流程

- 每个新交易日收盘后运行一次 `paper`；
- 核对待处理目标、次日开盘理论成交、现金、份额、分红和费用；
- 遇到数据延迟或漏跑时确认没有历史补成交；
- 至少观察 120 个交易日并经历一次完整状态切换。

### C. 最后决定是否扩展

- 只有参数邻域与 holdout 都显示一致的回撤改善，才研究 3–5 个宽基 ETF；
- 只有免费数据稳定性成为主要瓶颈，才评估授权数据源；
- 只有真实纸面流程稳定，才讨论券商适配；
- 任何阶段都不通过自动调参来修饰未达标结果。
