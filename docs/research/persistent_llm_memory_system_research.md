# 持久化、多层 LLM 记忆系统：研究与推荐设计

> 研究快照：2026-10-27（Asia/Shanghai）
> 范围：长期人机交互中的跨会话记忆，不讨论模型权重微调；本文只做系统设计，不含实现代码。
> 证据口径：优先论文原文、作者/项目官方仓库与官方文档。论文和项目方公布的基准数字均视为“作者报告”，不等同于本项目已复现。
> 详细实现级设计：[持久化多层 LLM 记忆系统：详细技术设计与代码框架](./persistent_llm_memory_system_technical_design.md)

## 1. 结论先行

推荐采用一套“事件溯源 + 分层派生记忆 + 混合检索 + 双路径写入 + 可撤销治理”的架构：

1. **原始交互事件是证据，不是直接提示词。** 保存不可原地改写、可按策略删除的原始事件；所有摘要、画像和反思都必须能追溯到事件。
2. **把上下文、记忆和授权分开。** 上下文窗口是本轮模型输入；持久记忆是外部状态；授权仍由系统策略决定。任何记忆都不得自行扩大工具权限。
3. **首版使用 PostgreSQL 作为唯一事实源。** 用普通表保存事件、记忆、版本、关系和审计；用 PostgreSQL 全文检索与 `pgvector` 做混合召回。不要一开始引入图数据库。
4. **设置五层记忆。** 原始事件、工作记忆、情景记忆、语义/用户画像、程序性/反思记忆，各有不同写入门槛、寿命和检索权限。
5. **情感强度只能是辅助信号，不能单独触发永久保存。** 高情绪可能意味着重要，也可能只是短暂状态、敏感信息或对系统的操纵。情绪首先影响当前回应方式；只有与用户明确记忆意图、长期效用、重复证据或未来承诺等信号共同成立，才影响长期保存。
6. **热路径只做确定且紧急的写入，复杂抽取放到后台。** 这样不让每次回复承担额外模型调用延迟，也便于合并、冲突检查和安全审查。
7. **更正不是覆盖，遗忘不是立刻删除。** 事实变化使用双时态和 `supersedes` 关系保留历史；低价值记忆先降低检索权重、再归档、最后按保留策略删除。
8. **先建立评估集，再增加“智能”。** 第一阶段只做显式记忆、稳定偏好和可核实承诺；图关系、自动反思、情绪驱动晋升都要在离线评估证明收益后再启用。

这套设计吸收了 Generative Agents 的重要性/反思、MemGPT/Letta 的分层上下文管理、LangMem 的热/后台双路径、Zep/Graphiti 的时态与冲突表示，以及 A-MEM/HippoRAG 的关联检索；但不照搬它们的固定阈值、提示词或自报基准。

## 2. 先纠正几个容易导致错误设计的前提

### 2.1 “上下文过长导致记忆丢失”只说对了一半

模型本身并不会在 API 调用之间自动拥有持久记忆。真正的问题有三层：

- **窗口容量**：历史文本放不下；
- **有效利用**：即使放得下，长上下文中的信息也可能难以被准确使用；
- **跨会话状态**：新会话若未重新注入相关状态，模型根本看不到过去。

因此，增大上下文窗口不是持久记忆方案；全量保存聊天记录也不是，因为“存下来”不等于“能在正确时刻检索、辨别新旧并安全使用”。MemGPT 把这一问题描述成分层虚拟上下文管理；LongMemEval 则直接评估信息抽取、跨会话推理、时态推理、知识更新和拒答，说明仅做长上下文或普通相似度检索并不够。[MemGPT 论文](https://arxiv.org/abs/2310.08560)；[LongMemEval 论文](https://arxiv.org/abs/2410.10813)

### 2.2 “情绪越强就越应该长期保存”是危险的逻辑跳跃

Generative Agents 的确让 LLM 对记忆的“poignancy”打 1–10 分，并与新近性、相关性共同排序；它在模拟角色实验中有效，但论文没有证明这套分数适用于真实用户的长期画像，也没有证明跨模型、跨语言稳定。[Generative Agents 论文，第 4.1–4.2 节](https://arxiv.org/abs/2304.03442)

高情绪文本可能是：

- 一次性的挫败、玩笑、角色扮演或夸张表达；
- 健康、关系、创伤等高敏感信息；
- 攻击者刻意制造的“高显著性”内容，用来挤占检索或污染记忆；
- 需要立刻关怀、却不适合永久保存的临时状态。

所以情感强度应主要影响**当下响应优先级和短期工作记忆**，长期保留必须经过其他证据。本文把这一点设为硬约束，而不是可调权重。

### 2.3 “保存越多，记得越好”通常不成立

过度写入会带来重复、冲突、旧事实干扰、检索噪声、隐私风险和模型成本。LangMem 的官方概念文档也明确指出，集合式记忆存在过抽取导致精度下降、欠抽取导致召回下降的平衡问题。[LangMem Core Concepts](https://github.com/langchain-ai/langmem/blob/main/docs/docs/concepts/conceptual_guide.md)

### 2.4 “摘要等于事实”不成立

摘要、画像和反思都是模型生成的派生物，可能遗漏限定条件或加入错误推断。它们必须保存来源事件、生成模型/策略版本和置信度；回答关键问题时允许回查证据。Zep/Graphiti 把原始 episode 与派生实体/关系分层，是值得采用的方向。[Zep 论文](https://arxiv.org/abs/2501.13956)

### 2.5 “新的信息总是更真”也不成立

新内容可能是更正、状态变化、误解、低可信来源或攻击输入。冲突处理必须同时考虑有效时间、记录时间、来源和用户确认；不能只按最后写入获胜。

## 3. 研究对象与可迁移结论

| **Reflexion** | 将任务反馈生成文字反思，放入 episodic buffer，供后续尝试使用 | 适合保存失败教训、验证过的策略和任务后复盘 | 它不是通用用户记忆或长期画像系统；自我反思未经验证不能晋升为规则 | 仅作为程序性/反思层的证据来源之一。[论文](https://arxiv.org/abs/2303.11366)；[官方仓库](https://github.com/noahshinn/reflexion) |

### 3.2 研究共识与仍未解决的问题

相对稳定的共识：

- 必须区分当前上下文与外部长期存储；
- 单纯向量相似度不足，时间、关键词、实体、来源和任务相关性都重要；
- 原子记录比整段会话摘要更利于检索和更新；
- 背景巩固能降低前台延迟，并更适合去重和反思；
- 更新、冲突、拒答和删除与“记住”同样重要；
- 所有派生记忆都应有来源和版本。

尚未解决、不能假装已有标准答案的问题：

- 不同业务中“什么值得记住”没有通用权重；
- 情感分类器的跨语言、反讽和文化稳定性不足，且相关记忆基准几乎不评价这一点；
- 论文基准常由合成对话和 LLM judge 构成，不能直接代表真实长期用户满意度；
- 自动反思可能把推断固化成“事实”；
- 检索到正确证据不保证最终模型正确使用；
- 图结构的收益是否超过建图成本，必须在本项目的多跳查询上验证。

## 4. 推荐系统边界

### 4.1 目标

- 跨会话记住经授权、未来有用且可追溯的信息；
- 在有限 token 预算内提供与当前任务最相关、最新、可信的上下文；
- 能区分“用户曾经说过”“系统推断”“工具观察”“已经确认的事实”；
- 支持更正、时态变化、撤销、导出和可验证删除；
- 在记忆不足或冲突时明确拒答/询问，而不是补全；
- 可量化准确率、成本、延迟、安全性和隐私删除完整度。

### 4.2 非目标

- 不模拟完整的人类认知或医学意义上的情绪记忆；
- 不把全部聊天永久保存；
- 不让模型凭自身感觉改变权限、安全政策或系统人格；
- 不在第一版建设通用知识图谱、自动本体或自我改写提示词系统；
- 不把模型权重微调当作可删除、可审计的个人记忆。

## 5. 五层记忆模型

| 层级 | 名称 | 内容 | 典型寿命 | 写入方式 | 默认注入策略 |
|---|---|---|---|---|---|
| L0 | **原始事件层** | 用户/助手消息、工具结果、时间、会话、来源、授权决策 | 按合规和产品策略；不是默认永久 | 事件流追加；不做原地语义改写 | 不直接全量注入；仅在证据回查时取最小片段 |
| L1 | **工作记忆层** | 当前目标、未完成事项、近轮上下文、会话摘要、临时情绪状态 | 分钟到数天；任务结束即失效或降级 | 同步更新，可由确定性状态机维护 | 每轮按 token 预算注入 |
| L2 | **情景记忆层** | 有时间与场景的事件：“某日讨论并决定 X”“用户完成 Y” | 周到年；可衰减、归档 | 显式写入或后台从 L0 提取 | 查询相关时检索；必须携带时间和来源 |
| L3 | **语义/用户画像层** | 稳定偏好、长期目标、身份事实、约束、领域知识 | 直到被更正、到期或删除 | 高门槛后台合并；显式“请记住”可直接候选 | 高频且低敏感的少量核心画像可常驻，其余检索 |
| L4 | **程序性/反思层** | 经验证的交互规则、成功/失败教训、工作流程、回答风格 | 版本化长期；定期复核 | 只由可信反馈、重复成功或人工确认晋升 | 仅作用于匹配任务；不得覆盖系统/安全策略 |

两个关键补充：

- **核心记忆不是第六个事实源。** 它是从 L2–L4 生成的“小型常驻投影”，例如用户明确语言偏好和当前长期项目；可随时重建。
- **“不可变事件”不等于“永不删除”。** 不可变指禁止悄悄改写历史；合法删除请求应通过受审计的删除流程移除原文及所有派生索引。

## 6. 记忆记录的最小逻辑模型

每条派生记忆至少需要以下字段族；具体数据库字段可在实现阶段决定：

| 字段族 | 最小含义 |
|---|---|
| 身份与隔离 | memory id、tenant id、user id、agent id、namespace |
| 类型 | 层级、事实/偏好/事件/目标/规则/反思、主题 |
| 内容 | 原子、可独立理解的陈述；显式区分 observation / user-assertion / inference / reflection |
| 来源 | source event ids、说话者、输入通道、来源信任等级、是否来自外部网页/工具 |
| 双时态 | event time、valid from/to、recorded at、expired/revoked at |
| 置信与证据 | extraction confidence、support count、contradiction count、用户确认状态 |
| 价值信号 | 明确记忆意图、未来效用、重复度、新颖性、情感强度、任务相关性 |
| 治理 | 敏感级别、同意范围、保留期限、可导出/可删除、加密 key id |
| 生命周期 | candidate / active / superseded / archived / quarantined / deleted |
| 版本 | supersedes / superseded_by、抽取模型、提示/策略版本、创建者 |
| 检索 | embedding、全文检索字段、实体键、最近访问、访问计数 |

重要规则：

- `content` 是派生视图，`source_event_ids` 才是证据链；
- 用户原话、模型推断和工具观察不能混成同一种事实；
- 情绪标签描述的是“某时用户表达了某种情绪”，不是“用户就是某种人”；
- 模型生成的助手回复不能因为被重复检索就变成用户事实；
- 所有写入和检索都必须先按租户/用户/会话权限过滤，再做语义排序。

## 7. 写入与晋升策略

### 7.1 两条写入路径

**热路径（同步）**只处理低歧义、高即时价值的情况：

- 用户明确说“请记住/以后都这样”；
- 用户明确更正现有事实或偏好；
- 已确认的任务承诺、截止时间或安全约束；
- 当前会话的工作状态。

热路径先返回业务回答，再用轻量、可重试的事件写入；除非用户请求依赖立即记住，否则不要让复杂记忆抽取增加可感知延迟。

**冷路径（后台）**处理：

- 会话结束或空闲后的原子事实提取；
- 去重、冲突检测、版本连接；
- 情景聚类、摘要、画像更新；
- 反思与程序性经验候选；
- 衰减、归档、删除和索引维护。

LangMem 官方实现也明确区分 hot path 的主动工具写入与 background 的自动提取/巩固，支持这一拆分。[LangMem Hot Path](https://github.com/langchain-ai/langmem/blob/main/docs/docs/hot_path_quickstart.md)；[LangMem Background](https://github.com/langchain-ai/langmem/blob/main/docs/docs/background_quickstart.md)

### 7.2 写入先过硬规则，再做多维评分

不要把所有因素压成一个“总重要性分”后直接写入。正确顺序是：

1. **权限与来源门**：该来源是否有权创建这种记忆？
2. **敏感性门**：是否为秘密、凭证、金融/健康/第三方隐私等受限内容？
3. **事实类型门**：这是用户陈述、观察、推断，还是外部内容中的指令？
4. **冲突门**：是否与现有记忆冲突；是更正、状态变化还是不可信噪声？
5. **价值评分**：仅对通过前四门的候选做排序和层级决定。

建议的价值信号不是固定权重，而是一组可观测特征：

- **E：Explicitness**，用户是否明确要求记住；
- **U：Future utility**，对未来任务、承诺、偏好是否有可预期用途；
- **D：Durability**，信息是否稳定，而非短暂状态；
- **R：Repetition/support**，是否多次独立出现或被确认；
- **N：Novelty**，相对已有记忆是否新增有效信息；
- **A：Affective salience**，情绪唤醒/强度，仅作弱辅助；
- **C：Confidence**，抽取与实体归属是否可靠；
- **T：Trust/provenance**，来源信任等级；
- **S：Sensitivity risk**，敏感度和潜在伤害，作为强负向或人工确认门；
- **P：Poisoning risk**，是否包含指令化语言、越权企图或来自不可信工具内容。

### 7.3 情感信号的专门规则

- 情感只影响 L1 时，可以快速改变当前回应的语气、节奏和关注点；
- 进入 L2 时，只保存带时间的事件，如“用户在讨论发布失败时表达强烈沮丧”，并设置较短默认保留期；
- 晋升 L3 时，需要用户明确同意、重复稳定模式或明确长期需求，且保存为有限表述；
- 不把单次情绪推断为人格、心理状态或诊断；
- 对健康、创伤、关系等敏感主题默认不自动晋升；
- 负面情绪、紧迫措辞或大写/重复标点绝不能绕过来源与安全门；
- 用户可以选择“只在本次对话使用，不要记住”。

这能避免“情绪越大，永久权重越高”的认知偏差，也减少系统奖励戏剧化表达的反向激励。

Emotional RAG 在角色扮演数据上显示，情绪状态可以与语义相关性共同参与检索；2026 年的多因素价值模型则把情绪强度放在七个因素之一，并从下游目标校准权重。二者都更支持“情感是一个需要评估的特征”，而不是“高情绪就是永久记忆”的规则。[Emotional RAG](https://arxiv.org/abs/2410.23041)；[Learning What to Remember](https://arxiv.org/abs/2606.12945)

### 7.4 晋升条件

| 目标层 | 至少满足 |
|---|---|
| L1 工作记忆 | 与当前任务有关，且不过安全门 |
| L2 情景记忆 | 明确事件、可定位时间/场景、来源可追溯、未来有潜在用途 |
| L3 画像/语义 | 明确用户陈述或多次一致证据；冲突已处理；敏感信息有合适同意 |
| L4 程序/反思 | 可观测结果支持，最好多次成功/失败或人工确认；不可来自单个外部网页/工具指令 |

任何未满足晋升条件的内容仍可留在有期限的 L0/L1，而不是强行丢失或永久化。

## 8. 巩固、衰减与遗忘

### 8.1 背景巩固

每次会话结束或达到事件/时间阈值后：

1. 把会话切成原子事件候选；
2. 与现有同主题记忆做混合召回；
3. 判定新增、重复、补充、冲突、状态变化或无操作；
4. 新建派生记忆或追加新版本，不改写证据事件；
5. 仅在有足够证据时生成更高层画像/反思；
6. 保存每个结论引用的事件；
7. 对敏感或高影响候选进入待确认/隔离队列。

Generative Agents 用重要性累计触发 reflection，并要求高层洞察引用底层记录；A-MEM 则用原子 note 和链接让新信息影响旧表示。本文采用“引用证据 + 动态关联”，但拒绝无版本的历史重写。[Generative Agents](https://arxiv.org/abs/2304.03442)；[A-MEM](https://arxiv.org/abs/2502.12110)

### 8.2 衰减只先影响可见性，不直接决定真伪

建议把“强度”拆为：

- 检索强度：最近/频繁/明确使用会提高；
- 事实置信：证据、来源、用户确认决定；
- 保留级别：敏感度、合规、用户意图决定。

旧但稳定的生日、过敏约束或长期项目不能仅因很久没提而被当作假；频繁被检索的错误也不能因此变真。MemoryBank 的指数遗忘与“回忆会强化”可用于低风险情景记忆的排序实验，但其论文明示这是简化探索模型，不应作为自动删除规则。[MemoryBank 第 2.3 节](https://arxiv.org/abs/2305.10250)

### 8.3 生命周期

`candidate → active → superseded / archived / quarantined → deleted`

- **candidate**：抽取成功但尚未满足长期晋升条件；
- **active**：可被检索使用；
- **superseded**：被更正或状态变化替代，历史查询仍可见；
- **archived**：默认不召回，只在显式历史查询中使用；
- **quarantined**：来源/安全异常，禁止注入模型；
- **deleted**：源事件、派生记录、embedding、全文索引、缓存和图副本均进入删除流程。

## 9. 冲突与时间：双时态是必需项

每条可能变化的事实需要两条时间轴：

- **有效时间（valid time）**：现实中何时成立；
- **记录时间（transaction/recorded time）**：系统何时知道或修改它。

例如：10 月 27 日用户说“我从 10 月 1 日开始改用 VS Code”。有效时间是 10 月 1 日，记录时间是 10 月 27 日。

冲突处理至少区分：

1. **更正**：“我刚才说错了”；
2. **状态变化**：“以前喜欢深色，现在喜欢浅色”；
3. **并存限定**：“工作电脑深色，手机浅色”；
4. **来源冲突**：用户陈述与外部文档不同；
5. **低可信推断冲突**：模型画像与用户明确说法不同。

决策顺序应是来源权限与明确程度 → 时间范围 → 上下文限定 → 证据数量/置信度，而不是“最新一条无条件获胜”。Zep/Graphiti 用四个时间字段保存事实有效区间与系统记录区间，并通过使旧边失效来保留历史，这一思想可先在 PostgreSQL 中实现，不必立即采用图数据库。[Zep 第 2.2.3 节](https://arxiv.org/abs/2501.13956)

## 10. 检索与上下文组装

推荐流程：

1. **需求判定**：本轮是否需要长期记忆；查询属于当前状态、历史事件、偏好、关系、多跳还是程序经验；
2. **权限过滤**：tenant/user/agent/namespace、同意范围、敏感等级、用途；
3. **查询展开**：关键词、实体、时间范围和可能的同义表达；
4. **并行候选召回**：向量语义、PostgreSQL 全文检索、精确字段、时间过滤、最近情景；若内部评估证明原生全文排序不足，再评估 BM25 扩展；
5. **合并与去重**：RRF 或同类排名融合，保留多样性；
6. **信任门**：排除隔离、越权、无来源或与任务无关的指令型记忆；
7. **时态/冲突解析**：当前问题取当前有效版本，历史问题按指定时间取版本；
8. **重排**：相关性、来源、置信、时间、重要性、强度和敏感风险共同决定；
9. **证据打包**：在 token 预算内给出原子记忆、时间、置信和引用 id；
10. **回答后记录**：记录哪些记忆被用到、是否有用户纠正，不自动把模型回答写回用户事实。

检索分数可视为多信号组合，但**权限、来源信任、隔离和敏感性是前置门，不是能被相似度抵消的负权重**。

LongMemEval 的结果支持 session 分解、事实增强索引和时间感知查询；Zep 使用语义、全文、图邻域与多种 reranker；Mem0 2026 的当前说明也转向语义、关键词与实体的多信号检索。三者共同支持“混合检索优先于单向量检索”。[LongMemEval](https://arxiv.org/abs/2410.10813)；[Zep](https://arxiv.org/abs/2501.13956)；[Mem0 当前仓库](https://github.com/mem0ai/mem0)

## 11. 存储与服务拓扑：最小但完整

### 11.1 首选

**PostgreSQL + pgvector + PostgreSQL 全文检索**：

- 事件表：L0 原始事件与来源；
- 记忆表：L1–L4 原子记录、状态、双时态、治理字段；
- 版本/关系表：supports、contradicts、supersedes、derived-from、related-to；
- embedding 列：语义召回；
- 全文索引：关键词与专名召回；
- 审计表：写入、读取、晋升、纠正、删除、策略版本；
- 后台队列：可先用数据库队列/现有任务系统，避免新增消息中间件。

这能在一个事务边界内处理隔离、时态、版本、删除和检索，降低首版运维成本。普通关系表已经能表达一到两跳关系；只有在真实查询显示多跳遍历成为主要瓶颈时，才需要图数据库。

### 11.2 可选升级

若离线评估同时满足以下条件，再评估 Graphiti/Neo4j 或其他图后端：

- 多跳/关系问题是核心流量，而非偶发需求；
- PostgreSQL 关系表 + 混合检索的证据 recall@k 达不到目标；
- 图方案的准确率收益超过建图 LLM 成本、写入延迟与运维成本；
- 实体解析、时态边和删除传播在本项目数据上可控；
- 完成租户隔离、认证授权与注入防护。Graphiti 官方明确其参考 MCP/REST 服务没有认证、授权和 prompt-injection 防护，不能直接暴露到生产网络。[Graphiti 官方仓库安全说明](https://github.com/getzep/graphiti)

### 11.3 不建议首版采用

- 多个向量数据库与图数据库并存；
- 模型自主决定数据库 schema；
- 全量聊天记录每轮重摘要；
- 通过微调写入个人事实；
- 让一个“记忆代理”拥有无限制的读写和工具权限；
- 为“以后可能有用”预建跨模型、跨供应商抽象层。

## 12. 隐私、删除与安全

### 12.1 隐私默认值

- 最小化收集：只保留实现用户价值所需字段；
- 分类同意：偏好、长期目标、敏感经历、第三方信息分别控制；
- 用户可见：提供“系统记住了什么、为何、来自哪里、何时失效”；
- 用户可改：更正生成新版本并使旧版本失效；
- 用户可删：删除不能只删文本行，必须覆盖派生摘要、embedding、全文索引、关系边、缓存和后续备份到期；
- 强隔离：tenant/user namespace 和数据库行级策略先于检索；
- 加密：传输、存储和备份加密；高敏感类别可使用用户级密钥以支持加密擦除；
- 不存秘密：密码、API key、验证码、私钥和访问令牌禁止进入长期语义记忆。

### 12.2 删除协议

1. 冻结待删对象，阻止新检索；
2. 沿 `derived-from` 找到所有派生记忆和索引副本；
3. 删除或加密擦除原始事件与派生数据；
4. 清理 embedding、全文索引、图边、缓存和导出；
5. 对备份记录最晚消失时间；
6. 生成不含原文的删除审计证明；
7. 用 canary 查询验证不可再召回。

### 12.3 记忆投毒威胁模型

持久记忆把一次恶意输入变成跨会话控制通道。2026 年研究报告了“sleeper memory poisoning”：外部网页/文档诱使代理写入伪造用户记忆，之后在别的会话被重新激活；另一项研究把记忆搜索本身定义为信任边界，指出相似但上下文不适当的记忆可造成跨域泄漏、谄媚、工具调用漂移和 jailbreak。数字来自论文作者实验，尚未在本项目复现，但威胁机制与任何自动写入系统直接相关。[Hidden in Memory](https://arxiv.org/abs/2605.15338)；[Beyond Similarity / MemGate](https://arxiv.org/abs/2606.06054)

最低防线：

- **来源绑定**：每条记忆标注 user / assistant / tool / web / admin；外部内容无权写用户画像或程序规则；
- **写入门**：把外部文档中的“记住、忽略规则、以后执行”视为数据，而非授权；
- **读取门**：检索结果仍是不可信数据，不能放到高优先级系统指令区；
- **权限分离**：记忆只能提供事实候选，不能授权转账、发信、删文件或提升权限；
- **程序记忆白名单**：只有用户明确要求、系统管理员发布或经验证反馈流程产生的规则可进入 L4；
- **敏感动作再确认**：历史记忆不能替代当前高风险操作确认；
- **完整性与审计**：记录来源、哈希/签名、策略版本、访问者和变更链，支持快照回滚；
- **限流与异常检测**：监测短时间大量写入、极端显著性、重复指令和跨主题召回；
- **隔离队列**：可疑候选不参与检索，等待自动复核或人工确认；
- **攻击评估**：覆盖写入、跨会话存活、召回和最终动作四阶段，而不是只测关键词过滤。

OWASP 的 Agent Memory Guard 项目把读写中介、来源类别、策略、取证事件和快照回滚作为防护面，可用于威胁建模参考，但其自报基准同样需要独立复现。[OWASP Agent Memory Guard](https://github.com/OWASP/www-project-agent-memory-guard)

## 13. 评估体系

### 13.1 公共基准

- **LongMemEval**：500 个问题，覆盖信息抽取、跨会话推理、时间推理、知识更新和拒答；适合主回归集。[论文](https://arxiv.org/abs/2410.10813)；[官方仓库](https://github.com/xiaowu0162/LongMemEval)
- **LoCoMo**：长周期、多会话对话，包含问答、事件摘要和多模态对话任务；适合个人对话长期记忆，但公开数据规模和论文全部语料口径要仔细核对。[论文](https://arxiv.org/abs/2402.17753)；[官方仓库](https://github.com/snap-research/LoCoMo)
- **LongMemEval-V2**：2026 年扩展到 agentic context 和“有经验同事”式任务，可作为后期程序/经验记忆测试，不应替代面向真实用户的内部集。[官方仓库](https://github.com/xiaowu0162/LongMemEval-V2)
- **记忆投毒集**：采用公开攻击生命周期思路，加上本项目工具和中文输入的红队集。[MPBench 官方仓库](https://github.com/Digital-Trust-Lab/mp-bench)

### 13.2 必须自建的评估集

公共基准几乎不能回答“中文情绪表达该不该长期保存”。需要从产品场景构造经脱敏和授权的金标：

- 明确“记住/别记住/忘掉”；
- 同一偏好随时间变化；
- 一次性强情绪与长期稳定需求的对照；
- 反讽、否定、转述、角色扮演；
- 第三方隐私和高敏感内容；
- 外部网页/工具结果中夹带记忆指令；
- 模型自身错误回答不得回写成用户事实；
- 当前事实、历史事实和“不知道”的区分；
- 多跳关系问题；
- 删除后通过改写查询仍不可召回。

### 13.3 指标分层

| 阶段 | 核心指标 |
|---|---|
| 写入 | 应写 precision/recall、错误归属率、重复率、敏感信息误存率、投毒写入成功率 |
| 巩固 | 事实保持率、摘要新增错误率、冲突识别率、证据覆盖率、版本正确率 |
| 检索 | evidence recall@k、precision@k、MRR/nDCG、时间版本准确率、跨租户泄漏率 |
| 回答 | 有证据答案正确率、拒答准确率、引用忠实度、过时事实使用率 |
| 生命周期 | 更正生效延迟、删除完整率、删除后再召回率、备份到期一致性 |
| 系统 | p50/p95 延迟、每轮 token/模型成本、后台积压、存储增长、失败重试率 |
| 用户 | 记忆有用率、打扰率、纠正次数、用户主动删除/禁用率、信任反馈 |

必须分别报告：

- 只检索是否正确；
- 模型拿到正确证据后是否回答正确；
- 端到端是否正确。

否则容易把检索失败、读取失败和生成幻觉混成一个分数。

### 13.4 对照与准入线

每次增加复杂机制都要与这些最小基线比较：

1. 最近 N 轮；
2. 会话摘要；
3. 仅向量检索；
4. 向量 + 全文 + 时间过滤；
5. 完整推荐系统；
6. 可选图方案。

只有当机制在关键指标上稳定提高，并且没有造成不可接受的成本、隐私或安全回退，才进入生产。不要只比较平均最终答案分数；知识更新、拒答、删除和投毒必须设硬门槛。

## 14. 分阶段落地路线

### 阶段 0：定义和基准（先做）

- 冻结记忆类型、来源等级、敏感分类、双时态语义和删除语义；
- 建立 200–500 条中文场景金标与攻击集；
- 确定 token、延迟、存储和模型调用预算；
- 明确哪些类别永不自动记、哪些必须询问用户；
- 先跑“最近 N 轮、摘要、向量检索”基线。

退出条件：评审者对同一条语句是否应保存、保存在哪层、何时失效有足够一致性；否则模型也无法可靠学习门槛。

### 阶段 1：最小可信记忆

- PostgreSQL 事件源 + L1 工作记忆；
- 只支持用户显式记忆、显式更正、显式删除；
- 少量结构化 L3 偏好/长期约束；
- PostgreSQL 全文 + pgvector 混合检索；
- 记忆查看、来源、编辑、删除和审计；
- 不启用情绪自动长期保存、不启用自动反思、不启用图数据库。

退出条件：高写入精度、零跨租户泄漏、删除验证通过，且比最近 N 轮/摘要基线明显提升。

### 阶段 2：后台情景记忆与时间

- 会话后自动提取 L2 情景记忆；
- 引入多维写入门、候选状态、双时态、冲突/更正；
- 增加衰减、归档和定期巩固；
- 情感只影响 L1 与 L2 候选排序；
- shadow mode 运行一段时间，让人审查“本来会保存什么”。

退出条件：公共基准和内部集上，知识更新/时间推理/拒答均提升，敏感误存率与投毒率低于门槛。

### 阶段 3：受控画像与程序性记忆

- 稳定信息从 L2 晋升 L3；
- 经验证的任务反馈生成 L4 候选；
- 高影响规则需用户/管理员确认；
- 增加反思引用、版本、回滚与过期复核；
- 完成读写双安全门和长期投毒红队。

退出条件：程序记忆对真实重复任务有净收益，且不会把外部内容或模型幻觉提升为规则。

### 阶段 4：按证据决定是否上图

- 只针对多跳失败案例评估 Graphiti/HippoRAG 或 PostgreSQL 关系扩展；
- 比较 evidence recall@k、端到端正确率、写入延迟、图构建成本、实体错误、删除传播和运维复杂度；
- 如果收益不显著，保留 PostgreSQL 架构。

这条路线刻意延后最昂贵、最难治理的自动反思和图结构，优先建立可纠正、可删除、可评估的可信底座。

## 15. 推荐决策

### 15.1 推荐采用

- PostgreSQL + pgvector + PostgreSQL 全文检索作为首版；
- 事件溯源和派生记忆分离；
- 五层记忆、双路径写入、双时态、版本/证据链；
- 情绪作为弱辅助和当前响应信号；
- 显式记忆优先、后台巩固随后；
- 权限/来源/敏感性硬门先于任何分数；
- 用户可查看、更正、删除；
- 先 shadow、再灰度、最后自动化；
- 用 LongMemEval/LoCoMo 加内部中文集和投毒集做端到端评估。

### 15.2 暂不采用

- 仅凭情绪高分永久保存；
- 生成式摘要覆盖原始证据；
- 以访问频率决定事实真伪；
- 每轮同步运行复杂记忆代理；
- 首版上 Neo4j/Graphiti；
- 将 Mem0、Zep 或 A-MEM 的项目方基准直接视作本项目结果；
- 让反思或外部网页写入系统规则；
- 把记忆当授权或高风险操作确认。

### 15.3 需要产品方最终确认的变量

系统设计可以给出默认值，但以下是业务决策，不能由模型替代：

- 是否默认开启长期记忆，还是明确 opt-in；
- 原始事件和各层记忆的保留期；
- 哪些敏感类别允许保存，是否需要逐类同意；
- 用户能否关闭情绪分析；
- 可接受的 p95 延迟和每用户月成本；
- 删除后备份最长保留窗口；
- 共享设备、家庭账户或团队账户的身份边界；
- 是否允许跨 Agent 共享记忆；
- 出现冲突时何时询问用户，而不是自动决策。

## 17. 证据边界

- 本文没有运行任何仓库或重现实验；“成熟度”来自论文范围、官方文档、代码仓库结构与当前维护状态的静态核对。
- 各项目使用的模型、提示、数据集版本和 judge 不同，横向数字不能直接排名。
- 2026 年的安全论文和项目较新，需要独立复现；但来源绑定、最小权限、可撤销和隔离属于低后悔架构选择，不应等到攻击复现后才补。
- 情绪驱动长期记忆缺少足够强的真实用户证据；本设计把它限制为弱信号，是风险控制下的工程判断。
- 最终选型必须由本项目的中文、长期、含更正与删除的真实分布评估决定。
